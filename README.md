# EscHotline

Офлайн-прошивальник AM32-ESC через MSP + FourWay — той самий протокол,
яким користується [am32.ca/configurator](https://am32.ca/configurator),
тільки офлайн і без браузера, для тих випадків, коли потрібно прошивати
багато ESC швидко.

## Навіщо цей проєкт

Сайт am32.ca/configurator робить те саме через браузер, але:
- вимагає інтернет і сам сайт (сторонній сервіс, який може змінитись/лягти);
- не пристосований під швидку конвеєрну прошивку великої кількості ESC
  поспіль людиною, яка не розбирається в прошивці;
- немає постійного технічного лог-файлу, щоб розібратись, якщо щось пішло
  не так.

Ця програма робить те саме напряму через послідовний порт (той самий
протокол MSP + FourWay, яким і сайт користується через FC), але:
- працює повністю офлайн, збирається в один `.exe` без встановлення Python;
- має режими "Хотспот" — для оператора, що просто підключає ESC один за
  одним, а програма сама читає, порівнює й прошиває лише те, що відрізняється
  (детальніше нижче);
- ніколи не перезаписує ESC, конфіг якого вже правильний (щоб не зношувати
  пам'ять флеш-контролера даремно);
- завжди перечитує й звіряє байти після запису (readback-verify) — жодного
  "стрельнув і забув";
- одна несправна ESC не зупиняє прошивку решти (ізоляція помилок по кожній
  ESC окремо);
- веде детальний технічний лог-файл (`~/.esc_hotline/logs/`), щоб
  можна було розібратись у незрозумілій ситуації заднім числом.

## Що вміє

Чотири вкладки:

- **Головна** — підключення до FC, сканування підключених ESC, порівняння
  з обраним файлом конфігу, ручне "Прошити все" (або авто-прошивка одразу
  після сканування).
- **Конфіг** — перегляд і редагування конфігу в реальних одиницях (KV
  мотора, кут випередження в градусах, PWM у кГц тощо, а не сирі байти),
  завантаження з файлу або зчитування з реального ESC, збереження у файл,
  запис на ESC з підтвердженням і показом що саме зміниться. Захист від
  випадкового редагування колесиком миші.
- **Хотспот** — режим "постав і забудь" для конвеєрної прошивки **всіх**
  ESC, підключених до FC, одразу: обрати конфіг і порт один раз, натиснути
  Старт, далі просто підключати ESC один за одним — програма сама виявляє
  підключення, перевіряє, прошиває необхідне й показує великий кольоровий
  сигнал "Готово! Можна відключати" (або "НЕ ВІДКЛЮЧАЙТЕ" поки триває
  запис).
- **Хотспот (лінія)** — той самий "постав і забудь", але для **одного**
  заздалегідь обраного виходу ESC замість повного сканування — зручно,
  коли на робочому місці завжди підключений лише один ESC за раз. Тут
  також можна налаштувати, скільки часу давати ESC на запуск/перевірку
  (крок 100 мс) — корисно, якщо один з ESC потребує довшого часу на
  завантаження, ніж інші.

Інтерфейс — англійська та українська (перемикач у верхньому правому куті).

## Як запустити

Два способи, обидва без встановлення Python:

- **`dist/EscHotline.exe`** — один файл, зібраний через PyInstaller
  ([scripts/build_exe.py](scripts/build_exe.py), або одним подвійним
  кліком через [scripts/build_exe.bat](scripts/build_exe.bat)). Може
  блокуватись Smart App Control на Windows 11 як неопідписаний файл —
  деталі в [docs/PROTOCOL_NOTES.md](docs/PROTOCOL_NOTES.md). Сам файл
  `.exe` не зберігається в цьому репозиторії — його потрібно зібрати
  самостійно одним зі скриптів вище.
- **[scripts/run_dev.bat](scripts/run_dev.bat)** (або ярлик "EscHotline
  (з коду)" на робочому столі) — запускає напряму з коду через віртуальне
  середовище (`.venv`), без консольного вікна. Потрібен вже налаштований
  `.venv` — дивись [requirements.txt](requirements.txt) /
  [requirements-dev.txt](requirements-dev.txt).

## Що потрібно

- Windows.
- Політ-контролер (FC) з прошивкою INAV, підключений по USB, з AM32-ESC
  на моторних виходах (до 12 штук).
- Файл конфігу `.bin` (184 байти) — знятий раніше з еталонного ESC або
  отриманий іншим шляхом.

## Структура репозиторію

- [`src/esc_hotline/`](src/esc_hotline) — увесь код програми.
- [`tests/`](tests) — pytest-набір (89 тестів).
- [`scripts/`](scripts) — запуск з коду й збірка `.exe`
  (`run.py`, `run_dev.bat`, `build_exe.py`, `build_exe.bat`).
- [`docs/`](docs) — технічна документація для розробника, детальніше нижче.

## Технічні деталі

Для розробника, що переписує/оновлює/виправляє код —
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): довідник файл-за-файлом
(навіщо кожен файл, що саме робить, як йдуть дані при прошивці крок за
кроком, чого остерегатись).

Хронологічний журнал рішень і статусів по ходу розробки (протокол MSP/
FourWay, формули полів конфігу, дрібні особливості/грабельки) —
[docs/PROTOCOL_NOTES.md](docs/PROTOCOL_NOTES.md).

конфігу, оркестрація EscManager на підробленому залізі, стан-машина
"Хотспот (лінія)", клампінг ручного лічильника).
